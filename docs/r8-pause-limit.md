# R8 관측 중단 상한 (#127)

## 적용한 결정

[#127의 최신 MVP 결정](https://github.com/jangy3079-oss/fish_InnpHacka/issues/127)에 따라
`config/cause_rules.yaml`의 `rules.R8.behavior.max_pause_hours: 16`을 적용한다.
16h는 합성 검증용 가정이며 현장 진단 기준으로 승인된 값이 아니다.

- 고품질 비비기 이상을 관측한 시간만 기존 6h 기준에 더한다.
- 연속 미관측(저품질·품질 없음·비비기 없음)은 누적하지 않고 pause한다.
- 미관측이 정확히16h이면 이전 이상 누적을 보존한다. 16h를 초과한 주기에 누적을 비운다.
  유효 관측 재개 주기는 미관측 시간에 포함하지 않는다.
- 유효 관측이 다시 들어오면 연속 pause 시간을 비운다. 비비기가 기준 미만이면 즉시 이상 누적도 비운다.
- 정상 환경·명시적 특보 없음·ready 조건을 잃거나 stream 주기가 끊기면 기존처럼 초기화한다.
  반복된 서로 다른 pause를 합산하는 전체 이력 만료 정책은 추가하지 않는다.
- 미관측 중 과거 R8을 현재 원인으로 게시하지 않는다. 현재 점수 게이트도 유지한다.

R5의 최근3개 완료24h 평균·상승·관측 비율 조건과 R5/R8 동시 후보·동점 순위는 유지한다.
2h 잡음 유예, 최근 비비기만으로 R5 일괄 제외, 낮은 현재 점수에서 이전 R5/R8 자동 유지는
#127에서 보류했으므로 적용하지 않는다. 원인 누락률·겹침을 숨기려고 조건을 조정하지 않는다.

## 설정 배포

`max_pause_hours`는 양수인 필수 값이다. 코드와 저장소 YAML을 함께 배포하고,
`ROCKFISH_CONFIG_DIR` 등 사용자 설정 사본에도 키를 추가한다. 누락·0·음수는 ConfigError로 거부하며
조용히 기본값이나 오래된 설정으로 대체하지 않는다. 전체 묶음 검증은 기존 ConfigLoader와 관리자 수정 API가 공유한다.

설정 revision 변경 시 엔진 이력은 기존처럼 초기화한다. DB 분석은 입력 창을 순서대로 다시 평가한다.
DB 스키마·HTTP 응답 필드는 바꾸지 않으며 원격 DB/실계정/운영 설정은 수정하지 않는다.
기존 원인 evidence에 `rubbing_pause_hours`(연속 미관측 시간)를 추가한다.

## 검증과 후속 작업

단위 회귀는 정확히16h/초과16h, 새6h 관측 필요, 반복 pause, 현재 점수 게이트,
정상 관측·특보 unknown/active 초기화, 다른 YAML 상한, 누락/잘못된 설정을 확인한다.
기존 R5 추세·동시 R5/R8 후보·저품질·환경·stream·가두리·설정 revision 회귀도 유지한다.

```sh
python -m unittest tests.test_cause_extended -q
python -m unittest discover -s tests -q
python -m pipeline.validate --seeds 10 --out ../validation127-after
```

변경 전후 동일10개 시드의 VC-03·커버리지 비교는 `r8-pause-validation.json`에 기록한다.
main5e41409와 비교해 10seed 전체 평가 요약이 동일했다. 질병은10/10, 기생충은9/10이며
평균 원인 커버리지는 각각0.6644와0.1528로 전후 동일하다. 기생충9/10과 원인 누락은 남은 한계다.
이 합성 평가에서는 요약 지표 변화가 없었으며, 16h 경계 동작은 별도 단위 테스트로 검증했다.
전체 회귀381개는353개 통과·선택 비전28개 제외(452.137s), 이후 추가한 R5 현재 점수 게이트 회귀1개도 통과했다.
정답 라벨은 평가에만 사용하고 원인 엔진 입력에 넣지 않는다. 프론트 합성 파일의 기존
`scenario_label` fallback 정책은 유지한다. 실제 API/DB·VC 평가에는 라벨 fallback이 없다.

영무(백엔드)는 필수 설정 키 배포·이력 초기화·DB 순차 재생 범위를 확인한다.
데이터/모델은 관측 공백과 원인 커버리지 한계를 검토하고, 운영·비전은 실제 입력의 품질/신선도를 검증한다.
`cause[].display`/`cause_source`/`cause_pending`·실제 관측 progress·해제 사유의 API와 화면 연결은
#127의 별도 후속 작업이다. 이번 PR 병합만으로 #127 전체를 종료하지 않는다.
