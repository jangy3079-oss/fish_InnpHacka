# 시연 리허설 기록 (프론트) — #205

시연 대본(#41)의 대표 시점에서 **프론트가 실제로 보여주는 값**을 기록합니다. 값은 현재 시연 데이터(`frontend/src/mocks/scenarios.json`, `python -m pipeline.frontend` 내보내기)를 프론트의 시연 코드로 계산한 결과이고, 서버 응답으로 잰 값이 아닙니다. 데이터를 다시 내보내면 값이 달라지므로, 시연 직전에 다시 확인합니다.

## 시연 준비 순서
1. `cd frontend && npm install && npm run dev` (목업 모드, 서버 없이 동작)
2. 브라우저에서 `http://localhost:5173`을 열고 **로그인**: 소개 화면의 "어민 화면 열기" → 어민 계정(김바다). 지자체 대시보드는 로그아웃 뒤 지자체 계정(박해양)으로 들어갑니다. 계정은 브라우저에 기억되므로 시연 전에 한 번 들어가 둡니다.
3. 화면 왼쪽 아래 "시연 모드 열기"에서 시나리오와 시각(슬라이더)을 고릅니다. 슬라이더 값은 프레임 번호(0~47)입니다.
4. 어민·대시보드·알림 화면 위쪽에 "합성 시연 데이터입니다. 실제 가두리 값이 아닙니다."가 항상 보입니다.

## 대본(#41)과 화면의 차이
- **t≈10 "지금은 정상입니다"**: 단계는 정상이 맞지만, 원인 카드에 "살펴볼 점: 섭식 저하"와 "사료 관리 권고"가 이미 나옵니다. 새 데이터(R7 반영)에서 t=10부터 R7이 나오기 때문입니다. 대본의 "정상" 장면은 t=5 이하로 잡으면 아무것도 나오지 않습니다.
- **t≈15 "경보는 내지 않고 사료를 줄이라고만 권합니다"**: 화면과 맞습니다(사료 관리 권고).
- **t=20→26 "주의 → 경고 → 위험"**: t=20 주의, t=25 경고, t=26 위험으로 맞습니다. 단, t=20의 원인은 "(임시)"입니다.
- **t=34 "피난처 소실"**: 맞지만 "(임시)" 원인입니다.
- **손익 카드 "유지, 월하장 이동, 조기 출하, 긴급방류"**: 위험 단계에서 "월하장 이동"이 추천으로 표시됩니다.
- **진단 요청**: 목업 모드에서는 버튼이 "시연: 진단 요청해 보기"이며 누르면 "시연 화면이라 실제로 접수되지 않습니다"가 나옵니다. 실제 접수·전달 문구는 쓰지 않습니다.

## 서버가 느리거나 안 될 때 (실제 모드로 시연할 경우)
- 실제 모드(`VITE_USE_MOCK=false`)에서는 시연 패널의 "**파일 재생으로 보기**"를 눌러 파일 데이터로 바꿀 수 있습니다. 자동으로 바뀌지 않으며, 파일 재생 중에는 배너에 "(파일 재생 중)"이 붙습니다. 다시 "서버 응답으로 보기"로 돌아올 수 있습니다.
- 서버 준비 중(503)이면 3초 간격으로 최대 3번 다시 시도하고, 3초가 넘으면 "분석을 준비하는 중입니다" 안내가 나옵니다.
- 시각을 바꾸면 아직 끝나지 않은 이전 시각의 요청은 취소합니다. 재생은 응답이 온 뒤에 다음 칸으로 갑니다.

## 확인한 것과 확인하지 못한 것
확인함
- 위 표의 값: 시연 코드로 계산한 결과(시연 데이터 기준)
- 목업 모드에서 로그인, 권한별 화면, 재생, 합성 표시, 시연 선택·진단 버튼의 저장 차단(저장 API 호출 0회)
- 실제 모드에서 서버가 없을 때 오류 안내가 뜨고 "파일 재생으로 보기"로 데이터가 나오는 것(브라우저)
- 가짜 서버로 요청 취소, 503 재시도, 한 응답을 세 호출이 공유하는 것

확인하지 못함(실측 없이 보장하지 않음)
- 실제 서버의 첫 요청 준비 시간과 준비 후 요청 한 번의 시간
- 서버 시연 응답이 이 문서의 값과 같은지(파일 데이터와 서버 재생은 같은 엔진이지만 직접 비교하지 않음)
- 서버 동시 요청 부하, worker 수, 접근 범위
